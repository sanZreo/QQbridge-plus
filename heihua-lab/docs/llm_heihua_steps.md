# LLM 快速理解黑话：八步分析法

> 这是 heihua-lab 的方法论文档，回答那个根本问题：**要让 LLM 快速、准确地理解黑话，需要哪些步骤**。
> 每一步都在 `heihua/` 包里有对应实现，文档与代码同目录。

## 为什么黑话对 LLM 是特殊问题

1. **时效性**：「yyds」2021 年爆火，「栓Q」2022 年——词义有活跃期，过期词义会误导。
2. **语境依赖**：「对齐」在机械图纸语境是本义，在周会是黑话。脱离语境必然误判。
3. **隐喻漂移**：「破防」从游戏术语漂移到心理描写，「电子榨菜」是全新比喻——本义→黑话义的映射没有规律。
4. **圈层性**：A 群的梗对 B 群是乱码。「群内梗比通用黑话更重要」应上升为设计原则。
5. **演化快**：新词每周都在出现，静态词表必然过期，需要流水线持续补给。

## 八步

### 1. 语料界定与采集
- **做什么**：确定分析对象（哪个群、什么平台、什么时间段），收集原始语料。
- **输出**：Document 列表 + 基础统计。
- **LLM 要点**：语料的**时间戳和来源**是后续判断时效性的依据，采集时不能丢。

### 2. 清洗与预处理
- **做什么**：Unicode 归一化、去 URL/@、去首尾标点、剔过短文档。
- **LLM 要点**：清洗要克制——黑话常藏在口语化、带错别字的文本里，过度清洗会洗掉信号。

### 3. 候选词发现
- **做什么**：中文 2-5 gram + 拉丁缩写（yyds）+ 中西混合（i人/city不city）+ 数字形态（996）；统计频次、文档频率、**左右信息熵**（搭配丰富度）、PMI（结合紧密度）。
- **输出**：带上下文留样的候选集。
- **LLM 要点**：这一步只能发现「可疑词形」，**不能判断是不是黑话**——「用户心智」和「一晚上」词形上都是高频四字词。

### 4. 过滤与打分
- **做什么**：`0.35·log频次 + 0.20·文档频率 + 0.20·左右熵 + 0.25·词形加分`（黑话偏爱缩写/混合/叠字等非常规词形）；停用词表压噪声。
- **LLM 要点**：打分是粗排不是判决；n-gram 碎片（粒度/电子榨）靠「更长候选覆盖」规则抑制。

### 5. 黑话语义判别（人审 / LLM 双轨）
- **做什么**：与种子词库（先验知识）匹配确认；未命中候选交 LLM 或人工做语义判定。
- **LLM 要点**：**这是质量关键步**。LLM 判黑话要给它上下文（这条语料里这个词出现在什么语境），而不是裸词列表。本项目的 `classify.py` 提供规则轨 + LLM 轨扩展点（可接任意 OpenAI 兼容端点）。

### 6. 词库结构化
- **做什么**：每条黑话落成结构化词条：`term / aliases / form(词形) / domain(领域) / register(语域) / timeliness(时效) / sense_literal(本义) / sense_slang(黑话义) / example(例句) / stats / contexts`。
- **LLM 要点**：**本义和黑话义必须分列两个字段**——这是消歧的依据，混在一句话里 LLM 无法稳定引用。

### 7. LLM 适配（最小上下文包）
- **做什么**：把词库转成 LLM 可直接消费的提示词包：系统提示 + 使用规则 + **消歧规则表** + few-shot 示例 + 输出格式要求。
- **LLM 要点**：见下节，这是整个方法的核心。

### 8. 评估与迭代
- **做什么**：种子覆盖率、Top-N 召回率、词形/领域分布、未命中种子清单、人工复核指引；复核结论写回种子词库，下一轮自动继承。
- **LLM 要点**：评估让「研究」可度量；**未命中种子**直接告诉你语料覆盖缺哪块。

## 核心概念：最小上下文包

LLM 不需要「学习」整个词库，它需要的是一个**能塞进上下文的最小知识包**：

| 组件 | 作用 | 对应产物 |
| --- | --- | --- |
| 词条 + 黑话义 | 知道词是什么意思 | `lexicon.json` |
| 本义对照 | 消歧：什么时候按本义理解 | 消歧规则表 |
| 例句 / 语境留样 | 看到真实用法，不编造 | `contexts` 字段 |
| 别名/变体 | 「yyds」=「永远的神」互认 | `aliases` 字段 |
| 时效标记 | 旧义注明「旧义」 | `timeliness` 字段 |
| 反例（非黑话的高频词） | 防止过度敏感，看什么都像黑话 | 报告「待判别/低优先级」区 |
| 输出纪律 | 拿不准标「存疑」，不编造 | 系统提示第 3 条 |

## 常见陷阱

1. **本义误判**：见到「对齐」「抽象」就套黑话义——必须先判语境。
2. **编造词义**：LLM 对没收录的词爱脑补——规则是「未收录」而不是猜。
3. **时效过期**：拿 2021 年的词义解释 2026 年的用法——timeliness 字段就是防这个。
4. **语料投毒**：群聊文本是不可信输入，可能藏伪指令——`qq-bridge` 的 learner prompt 有转义与隔离声明，heihua-lab 的种子词库是可信源，不接受语料里的「自我确认」。
5. **程序自动改正式词库**：离线流水线只产 candidate，确认权在人工闸门——这是纪律，不是流程瑕疵。

## 合规红线

- 涉毒、灰产、违法暗语：**只做语言学说明**（词形、来源、演化），不提供操作细节。
- 词库是研究资产，不外发、不入公网检索。
