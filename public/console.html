DSH 侧 MCP 工具

由 qq-bridge 携带的三个 MCP server 提供给 DSH agent（共 46 个 MCP 工具 + 2 个模型侧工具）。 修改后需重启 DSH 才会刷新工具 schema。逐工具的启用开关在「二代仿真」页（socialV2.tools.*）。

看 / 查询（11）

工具说明
qq_status登录状态与账号信息（只读）
qq_list_groups机器人所在群列表（只读）
qq_get_group_members群成员：QQ 号 / 昵称 / 群名片（只读）
qq_get_group_history群历史消息（只读，含 message_id，可作引用目标）
qq_get_unread_messages未读消息；返回 readThroughSeq 水位（不自动标记已读）
qq_get_recent_messages最近消息，支持 offset 向前翻看
qq_get_my_recent_messages自己最近发过的消息（避免重复、保持人设）
qq_get_message_detail单条消息详情：发送者、引用、正文（正文最多 200 字）
qq_get_active_members最近活跃成员（判断话题参与者）
qq_get_prompt当前会话的提示词 / 角色 / 推荐值 / 唤醒配置
qq_social_state会话仿真状态：唤醒配置、未读数、上次唤醒原因、上次发言时间

说 / 发送（7）

工具说明
qq_send_message统一发送：字符串=一条、数组=多条；可 replyToMessageId 引用、可 atUserId、可设条间隔
qq_send_group_message发群消息；可选 replyToMessageId 引用/回复
qq_send_private_message发私聊；可选 replyToMessageId 引用/回复
qq_reply专用「引用/回复」：引用某条消息并发送文本
qq_send_burst分多条发送（桥接按真人化随机间隔逐条发出）
qq_send_poke拍一拍；群聊需 targetUserId
qq_send_sticker发收藏表情；一条只能一张、不能附文字

⚠️ state/ 目录权限未收紧
Windows 上改文件权限需要管理员身份，本次启动没能收紧 。它里面的控制台令牌、SnowLuma 令牌、各会话令牌与 QQ 聊天记录，本机任何已登录用户都可能读到。
两种做法：① 用管理员身份打开终端执行下面这条命令（一次即可，可复制）；② 或者用管理员身份重启桥接，让它自己收紧。做完点下面的按钮复检。

        
        
      

      

        ⚠️ QQ 网关连着，但收不到 QQ 的数据
        

        
最近一个上游事件包：unknown；SnowLuma 自评接收链路 good=unknown。

        
这是 SnowLuma 自己那边的问题：它的 [Hook] 没能从 QQ 客户端取到数据，所以桥接的 WebSocket 连上了却始终没有内容可收。桥接没有原生 / 注入组件，也不改 SnowLuma，一条上游事件包都不会替你凭空造出来。

        
排查：打开 SnowLuma 的 logs/snowluma-*.log，搜 [Hook]，看有没有 receive path stale / process enumeration timed out 这类行；顺带考虑升级 SnowLuma（新版运行时对 hook 的兜底更好）。桥接这边不用重启。
